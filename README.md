# Rummikub ILP + PPO

ILP(Integer Linear Programming)로 루미큐브에서 가능한 행동 후보를 만들고, PPO(Proximal Policy Optimization)가 후보들의 장기적인 가치를 학습해 행동을 선택하는 하이브리드 실험 프로젝트입니다.

현재 환경은 PPO 플레이어와 ILP 플레이어의 2인 대전으로 구성됩니다. 조커를 제외한 104개의 타일을 사용하며, 각 플레이어는 14개의 타일로 시작합니다.

## 전체 구조

한 턴은 다음 순서로 진행됩니다.

```text
현재 손패와 테이블
        ↓
ILP로 유효한 행동 후보 생성
        ↓
동일한 다음 상태 후보 제거
        ↓
후보별 다음 손패·테이블을 feature로 변환
        ↓
PPO Actor가 후보 또는 타일 뽑기 선택
        ↓
환경에 행동 적용 및 reward 계산
        ↓
ILP 상대 행동 적용
```

ILP는 규칙을 만족하는 행동을 정확하게 탐색하고, PPO는 여러 유효 행동 가운데 어떤 행동이 장기적으로 유리한지 학습하는 역할을 맡습니다.

## 적용된 루미큐브 규칙

- 색상: `R`, `B`, `Y`, `K`
- 숫자: 1~13
- 동일한 색상·숫자 타일: 2장
- run: 같은 색상의 연속된 숫자 3개 이상
- group: 같은 숫자의 서로 다른 색상 3개 또는 4개
- 첫 등록: 손패에서 사용한 타일의 숫자 합이 30점 이상
- 등록 후: 기존 테이블 타일을 포함해 모든 세트를 재구성 가능

현재 버전에는 조커와 조커 교체 규칙이 구현되어 있지 않습니다.

## ILP 원리

### 1. 유효 세트 사전 생성

먼저 규칙상 가능한 모든 run과 group을 생성합니다.

- 각 색상에 대해 길이가 3 이상인 모든 연속 구간 생성
- 각 숫자에 대해 색상이 겹치지 않는 크기 3, 4의 모든 group 생성

현재 손패와 테이블에 실제로 존재하는 타일만으로 만들 수 있는 세트를 추려 ILP의 후보 세트로 사용합니다.

### 2. 결정 변수

후보 세트 `i`를 최종 테이블 구성에 사용할지를 이진 변수로 표현합니다.

```text
x_i = 1  후보 세트 i를 선택
x_i = 0  후보 세트 i를 선택하지 않음
```

### 3. 타일 수량 제약

각 타일은 손패와 테이블에 존재하는 개수보다 많이 사용할 수 없습니다.

```text
Σ(candidate i가 사용하는 tile t의 수 × x_i)
    ≤ 현재 사용할 수 있는 tile t의 수
```

이를 통해 하나의 타일을 여러 세트에 중복 사용하는 해를 막습니다.

### 4. 기존 테이블 보존 제약

테이블에 이미 놓인 타일은 재배열할 수 있지만 사라지면 안 됩니다.

```text
선택된 세트가 사용하는 tile t의 수
    ≥ 기존 테이블에 있던 tile t의 수
```

따라서 기존 세트 형태는 바뀔 수 있어도 모든 테이블 타일은 최종 세트 구성에 다시 포함됩니다.

### 5. 손패 사용 제약

행동 후보를 만들 때는 필요에 따라 손패를 한 장 이상 사용하도록 강제합니다.

```text
선택된 전체 타일 수 - 기존 테이블 타일 수 ≥ 1
```

첫 등록 전에는 테이블을 제외한 손패만 ILP에 전달합니다. ILP 해가 나온 뒤 실제로 사용한 손패 숫자의 합이 30점 이상인 후보만 유지합니다.

### 6. 목적함수

현재 ILP는 한 번의 행동에서 사용하는 손패 타일 수를 최대화합니다.

```text
maximize 선택된 전체 타일 수 - 기존 테이블 타일 수
```

즉, ILP 단독 정책은 장기적인 패 모양보다 현재 턴에 최대한 많은 타일을 내는 greedy 정책에 가깝습니다.

### 7. 복수 후보 생성

`solve_many()`는 CBC solver로 최적해 하나를 구한 뒤, 동일한 세트 조합이 다시 선택되지 않도록 no-good cut을 추가합니다.

첫 번째 해에서 선택된 변수가 `{x1, x5, x9}`라면 다음 제약을 추가합니다.

```text
x1 + x5 + x9 ≤ 2
```

이후 ILP를 다시 풀어 다음 해를 찾으며, 설정된 최대 후보 수까지 반복합니다.

서로 다른 ILP 해라도 적용 후 손패와 테이블의 타일 구성이 같을 수 있습니다. PPO 환경은 다음 상태의 타일별 개수를 signature로 만들어 이런 후보를 하나만 유지합니다.

## PPO 원리

### 1. 상태 표현

PPO가 받는 observation은 108차원입니다.

| 구간 | 크기 | 표현 |
| --- | ---: | --- |
| PPO 손패 | 52 | 각 색상·숫자 타일 개수 / 2 |
| 테이블 | 52 | 각 색상·숫자 타일 개수 / 2 |
| 덱 | 1 | 남은 타일 수 / 104 |
| 상대 손패 | 1 | `min(상대 손패 수, 30) / 30` |
| 등록 상태 | 2 | PPO와 상대의 `opened` 여부 |

52차원 타일 벡터는 다음 index 규칙을 사용합니다.

```text
index = color_index × 13 + (number - 1)
```

### 2. 후보 표현

각 ILP 후보는 행동을 적용한 뒤의 상태를 104차원 feature로 표현합니다.

| 구간 | 크기 | 표현 |
| --- | ---: | --- |
| 다음 손패 | 52 | 후보 적용 후 남는 PPO 손패 |
| 다음 테이블 | 52 | 후보 적용 후 구성되는 테이블 |

후보마다 환경을 복제하지 않고 ILP 결과의 `remaining_hand`와 `selected_sets`에서 다음 상태를 직접 계산합니다.

### 3. 행동 공간과 mask

`max_candidates=20`일 때 모델은 총 21개의 행동을 평가합니다.

- `0~19`: ILP 행동 후보
- `20`: 타일 뽑기

후보 수는 상태마다 달라지므로 존재하지 않는 후보의 logit은 action mask로 비활성화합니다. 타일 뽑기는 항상 선택할 수 있습니다.

### 4. Actor-Critic 구조

상태와 후보는 서로 다른 MLP encoder를 통과합니다.

```text
observation ─→ state encoder ───────────────┐
                                            ├─→ score head ─→ 후보 logit
candidate ───→ candidate encoder ───────────┘

state embedding ─→ draw head ─→ 타일 뽑기 logit
state embedding ─→ critic ────→ 상태 가치 V(s)
```

하나의 state embedding을 모든 candidate embedding과 결합하므로 후보마다 동일한 평가 함수를 공유합니다. mask 적용 후 categorical distribution에서 행동을 표본 추출합니다.

### 5. Reward

현재 reward는 손패 감소와 최종 승패를 중심으로 구성됩니다.

| 사건 | Reward |
| --- | ---: |
| PPO가 손패 타일 사용 | 타일당 `+1` |
| PPO 승리 | `+50` |
| ILP 상대 승리 | `-50` |
| 상대가 손패 타일 사용 | 타일당 `-0.2` |
| 타일 뽑기 | `-1` |
| 빈 덱에서 뽑기 | `-2` |
| PPO 턴 진행 | `-0.1` |

중간 reward는 타일을 내는 행동을 유도하고, 큰 terminal reward는 최종 승패를 반영합니다.

### 6. GAE

수집한 rollout에서 Critic의 상태 가치와 reward를 이용해 advantage를 계산합니다.

```text
δ_t = r_t + γV(s_{t+1}) - V(s_t)

A_t = δ_t + γλA_{t+1}
```

`γ`는 미래 reward의 할인율이고, `λ`는 bias와 variance의 균형을 조절합니다. 현재 기본값은 각각 0.99와 0.95입니다.

### 7. PPO clipped objective

이전 정책과 새 정책의 action 확률 비율을 계산합니다.

```text
r_t(θ) = π_θ(a_t | s_t) / π_old(a_t | s_t)
```

Actor는 다음 두 값 중 작은 값을 최대화합니다.

```text
r_t(θ)A_t
clip(r_t(θ), 1-ε, 1+ε)A_t
```

확률 비율을 일정 범위로 제한해 한 번의 update에서 정책이 지나치게 크게 변하지 않도록 합니다. 현재 `ε`은 0.2입니다.

전체 학습 loss는 Actor loss, Critic loss, entropy 보너스로 구성됩니다.

```text
total loss = actor loss
           + value coefficient × critic loss
           - entropy coefficient × entropy
```

Critic은 예측한 상태 가치와 GAE return의 MSE로 학습하며, entropy는 정책이 너무 일찍 하나의 행동에 고정되는 것을 완화합니다.

## ILP 상대

PPO의 상대는 동일한 ILP solver를 사용합니다.

- 첫 등록 전: 30점 조건을 만족하는 후보 중 사용 타일 수가 가장 큰 행동 선택
- 등록 후: 손패 사용량을 최대화하는 ILP 최적해 선택
- 유효한 행동이 없으면 타일 한 장 뽑기

따라서 PPO는 규칙 기반의 일관된 greedy 상대를 대상으로 학습합니다.

## 알려진 제한 사항

- 조커가 구현되어 있지 않습니다.
- `solve_many()`는 후보마다 ILP 모델 생성과 CBC 실행을 반복하므로 학습 속도가 느릴 수 있습니다.
- 각 유효 세트에 binary 변수 하나만 사용하므로 동일 run 또는 group을 타일 복사본으로 두 번 선택하는 경우를 완전히 표현하지 못합니다.
- ILP 목적함수와 중간 reward가 모두 즉시 많은 타일을 내는 행동을 선호합니다.
- PPO는 하나의 고정된 greedy ILP 상대에게 학습하므로 상대 전략에 과적합할 수 있습니다.
- 기본 평가는 게임 수가 적어 모델 간 작은 승률 차이를 안정적으로 판단하기 어렵습니다.
- observation이 106차원이었던 이전 checkpoint는 현재 108차원 모델과 호환되지 않습니다.

## 개선 방향

- 장기적인 손패 형태를 반영하는 ILP 후보 목적함수 추가
- 후보별 다음 턴 가능 세트 수와 고립 타일 수 feature 추가
- ILP 모델 재사용과 병렬 환경을 통한 학습 가속
- 여러 ILP 정책과 과거 PPO checkpoint를 이용한 상대 다양화
- self-play와 curriculum learning 적용
- 더 많은 seed와 게임을 이용한 승률 평가
